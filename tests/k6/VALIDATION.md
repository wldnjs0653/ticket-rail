# 검증 기록 — 2026-09-09

이 파일은 코드 검증 기록이다. 실제 서비스의 성능·복구 결과 보고서가 아니다.

| 구분 | 결과 | 범위 |
|---|---|---|
| JavaScript 로직 회귀 검증 | 23건 통과 | Node.js VM에서 k6 모듈·HTTP·시계를 모의 구현 |
| Python 분석기 회귀 검증 | 15건 통과 | 실제 Python 표준 라이브러리 실행, k6 나노초 타임스탬프 및 API별 지연시간 집계 호환 |
| 문법 검사 | 통과 | JavaScript 모듈·Bash·Python |
| 실행 스크립트 | 로컬 대역으로 확인 | 결과 디렉터리·종료 코드 전달·덮어쓰기 거부 |
| 실제 k6 실행 | 미실행 | 이 작업 환경에 k6 실행 파일 없음 |
| 실제 Backend·클러스터 검증 | 미실행 | 실제 접속 정보·테스트 데이터·배포 확인 필요 |

주요 회귀 사례: 네 단계 각각의 장애, 예상하지 않은 2xx, Queue 409, 좌석 409, verify 만료, 잘못된 admitted 본문, waiting 본문을 담은 500, 대기 시간 제한, HTTP 예외, 예약 데이터 부족·중복, VU 시간 예산, Ingress Host, 동시성 한 명 성공, 미관측·무표본·재실패·표본 부족, 실제 http_reqs 합산, summary와 Point 건수 불일치, 도중에 끝난 흐름.

추가 확인: 기본 600초 대기 설정에서 5초 이후 admitted 응답도 성공 처리하고, 긴 대기 상한에 따른 기본 VU 자동 할당은 100으로 제한하며, 종료 대기가 입장 대기를 조기에 끊지 않도록 설정했다.

코드 편집 환경에서 재현하려면:

```bash
node --experimental-vm-modules tests/test-k6-logic.mjs
python3 tests/test_analyzer.py
```

이 검증은 k6의 실제 스케줄러·Go 실행기·네트워크·Kubernetes를 검증하지 않는다. 실제 검증 순서는 README의 접속 설정 → Smoke → 실제 데이터 E2E → 합의한 시험이다. 숫자 ID와 DB의 유효 상태, 최신 API 계약, 실제 요청 발생률·중단 iteration·후속 업무 결과는 실행 환경에서 확인한다.
