# 로컬 검증 결과

2026-09-15, Linux에서 실제 k6 1.3.0 + Bash + jq + curl로 실행했습니다. 대상은 로컬 모의 HTTP/Prometheus 서버이며 **아래 숫자는 클러스터 성능 결과가 아닙니다.** 모의 서버와 시험 도구는 배포 ZIP에 넣지 않았습니다.

| 확인 항목 | 검증 결과 |
|---|---|
| smoke | HTTP 200, JSON status=ok, k6 종료코드 0 |
| load | 11개 구간을 각각 1초로 축소해 실행. 총 410건, 구간별 요청 수와 p95 집계, 종료코드 0 |
| queue | 19명의 신규 사용자, join→waiting→admitted 총 57 HTTP 요청, 대기 응답 19회·입장 19건, 종료코드 0 |
| e2e | join→입장→Hold→booking_id=123 수신, 종료코드 0 |
| 동일 좌석 경쟁 | 서로 다른 3명, Hold 1건·409 충돌 2건·예약 1건, 종료코드 0 |
| 응답 분류 | 200/409/429/404/500/302/접속 실패를 각 1회 발생시켜 7개 분류가 각각 정확히 1건임을 jq로 확인 |
| 큐 서버 시계열 | 모의 0→5→0 값을 처음·최대·마지막으로 집계. 전체 시계열은 JSONL에 보존 |
| 없는 지표 | 빈 시계열은 미측정, 빈 쿼리는 미설정. 큐 깊이를 0으로 바꾸지 않음 |
| 사용자 중단 | INT 신호 후 종료코드 130 기록. 수정 후 요청 38건의 부분 집계와 중단 보고서 보존 |
| 입장 후 조회 | TTL을 0.25초로 축소. 19개 조회 세션 시작·완료, 좌석 조회 76회 |
| DB 처리 | kubectl 대역으로 CONFIRMED/APPROVED 응답 처리와 스키마 오류 시 미측정 표시 확인. 실행 SQL이 BEGIN READ ONLY로 시작함을 확인 |
| 실행 의존성 | 배포 실행 코드에 Python·pip·Ansible 호출 없음. Bash 구문 확인 완료 |

실제 환경에서 남는 확인: URL·인증·테스트 데이터, 큐 정원과 TTL 구현, Prometheus exporter 이름·라벨, 실제 DB 스키마·상태, 클러스터 접근 권한, 자원 한계. 이 검증은 실제 PostgreSQL·Kafka·Redis·HPA 동작의 성공을 증명하지 않습니다.

## r2 보완 검증 (2026-09-15)

- `tests/guard-test.sh`: 정상 상태, Node NotReady, Ready 미달 30초, 재시작, OOMKilled, 배포 변경, 관측 실패 60초, DB Primary 실패, 메모리/디스크 부족, HPA 포화, Grafana 장애, 최근 60초 오류율의 추가 60초 지속, dropped_iterations, 태그 누락, 호스트 CPU, 회복 시 타이머 초기화를 오프라인 fixture로 검증했습니다. 중단·초기화 확인 출력 16개가 통과했습니다.
- 실제 k6 1.3.0 + 모의 Kubernetes/Prometheus/API를 연결해 사전 점검, smoke, 단계별 load의 정상 종료를 확인했습니다.
- 실행 중 Node NotReady를 주입해 실제 k6가 중단되고 종료코드 20, Node NotReady 사유, 부분 k6-summary.json, report.md가 남는 것을 확인했습니다.
- 필수 계획 지표를 빈 설정으로 바꾸면 k6 실행 전에 차단하는 것을 확인했습니다.
- 감시 프로세스를 강제로 종료하는 통합 시험으로 상위 실행기가 이를 감지하고 중단 사유를 남기는지 확인했습니다.
- FIFO→jq 실시간 집계가 정상 요청의 최근 구간 건수·오류율을 계산하고 원본 Point 파일을 남기지 않는 것을 확인했습니다.
- Ingress 도메인 자동 선택, DNS 실패, 인증서 검증 실패, 기존 .local 주소 거부를 명령 대역으로 검증했습니다. 실제 Let’s Encrypt 인증서를 발급하거나 사용자 클러스터에 연결한 검증은 아닙니다.
- 원본 config.example.json과 observability.json을 가져와 감시 기준과 쿼리, 새 도메인 자동 탐색 설정을 생성하는 것을 확인했습니다.

원본에 비어 있던 DB/Kafka 등 PromQL은 실제 서버 확인 없이 채우지 않았습니다. 보완판은 이를 조용히 생략하지 않고 계획 지표 점검에서 차단하거나 명시적으로 표시합니다.
- 큐 회복 기간을 5초로 축소한 통합 시험에서 k6 유입 종료 후 별도 서버 관측이 계속되고 최종 종료코드 0으로 보고서가 생성되는 것을 확인했습니다.

## r3 Ansible 복원 검증 (2026-09-15)

- Ansible Core 2.19.3으로 playbooks/final-load.yml의 syntax-check 통과.
- 실제 Ansible→Bash 감시 실행기→k6 1.3.0→모의 API/클러스터 순서로 최종 큐 시험 실행. 종료코드 0, Ansible failed=0, 실행 서버의 report.md와 컨트롤러 수거 압축파일 생성 확인.
- 사용자 작성 Python 프로그램은 추가하지 않았습니다. Ansible의 표준 Python 런타임·모듈은 사용합니다.
- 실제 원격 k6 서버 SSH 연결과 실제 클러스터 부하 실행은 수행하지 않았습니다.
- 필수 지표 미설정 상황에서 사전 차단된 결과도 압축·수거한 뒤 Ansible failed=1로 반환하는 것을 확인했습니다.
